> 事情是这样的。 最近我一直在用 agent 处理各种工作，在几个对话框之间来回切。 大家懂的，就 DeepSeek 侧边的那个对话框。 切过来，切过去，做不同的任务，找不同的聊天框。 我不是在用 AI，我是在给 AI 当调度器。 这正是 DeepSeek 那篇《Super-agent 设计探索》要解决的问题。 01 ｜ 我们用了两年 AI，动作一次都没变 你用 AI 的样子，其实一直没变： 说一句话，它想一想，调个工具，等结果，再回你一句。 这个循环叫 ReAct Loop。 循环有个前提：会话（session）。所有历史、所有工具结果都得装在同一次会话里，模型才知道自己在干什么。 于是产品长成一个样子：左边会话列表，右边对话框，用完点“新建会话”。 多 Agent 也一样，常见两种玩法。 Agent Team：一个主 Agent 带几个子 Agent 拆步骤。 多会话：一件事开一个窗口，靠人自己切换。 两种玩法共享同一个假设：人驱动，会话是容器，一次推进一件事。 在“你问它答”的年代这是对的，因为人一次只能问一件事。 但它有个天花板，而且跟模型无关：上限不是 AI 多聪明，是你还能盯得过来几件事。 ▲ 图 1｜旧模式：一…
