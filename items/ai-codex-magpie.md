> 把多家 AI 订阅接进 Codex：我的 Magpie 配置与踩坑记录 我一边用着 Codex 的订阅，一边还有 Cursor、WorkBuddy、DeepSeek 的额度，后来又加了 Grok。 问题不是没有模型，而是我想在 Codex 里把它们用起来：做复杂规划时用更强的模型，日常写代码、做审查时换更合适的，顺便把各家额度用起来。 以前要来回改配置，也不能按任务自动切换。后来我用本机网关 Magpie，把已有订阅接到同一个入口，并配了一组按任务分流的路由规则。下面记下我是怎么配的，以及实际碰到过的边界。 它是一个跑在自己电脑上的本地网关。把各家订阅和 API Key 加进去之后，已经接入的 Agent 就可以选用不同厂商的模型，不必为了一次切换反复改配置文件。 官网在这里： Magpie 本身是开源软件，采用 MIT 许可，我没有看到它另收软件费；模型调用仍然走你自己的订阅或 API。 它解决什么问题 按官网的说法，Magpie 会在本机运行一个网关，默认地址是 127.0.0.1:3425，并把不同厂商的 API 协议互相转换，包括流式输出和工具调用。这样，本来只认某一家接口的 Agent，才有可能用上另一家的模型。…
