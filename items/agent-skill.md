# 我用软连接，解决了多 Agent 工具的 Skill 管理问题

## 简介

AI 工具用久了，我发现，最后留下来经常用的 Skill，往往是自己搭出来的，或者是在大佬分享的 Skill 基础上，一点点迭代成适合自己…

## 详情

以下内容整理自原帖/文章（节选，未做编造；完整内容请见来源链接）：

> AI 工具用久了，我发现，最后留下来经常用的 Skill，往往是自己搭出来的，或者是在大佬分享的 Skill 基础上，一点点迭代成适合自己的版本。 别人分享的 Skill 可以帮我起步。用到自己的工作里，哪些步骤要保留、哪些规则需要补充、结果要按什么格式输出，都得慢慢调整。用得越多，改得越多，这套 Skill 也就越来越贴近自己的做事方式。 这是我自己的 Skill 仓库： 可同一台电脑上，AI 工具也会越装越多。Codex、Claude Code、WorkBuddy、DeepSeek……不同工具换着用，自己这套不断迭代的 Skill，就有了维护的问题。 每个工具都放一份，改完以后就得挨个更新。在一个工具里补了规则，换到另一个工具时，还得确认它有没有用上新版。Skill 越多，新增、改名、删除时要处理的地方也越多。自己好不容易迭代出来的方法，还得花精力保证每个工具拿到的是同一版。 我的做法就是用软链接。我把自己的 Skill 放在私有仓库里维护，再让支持读取本机 Skill 目录的 Agent，通过软链接找到同一份运行内容。以后更新有一个统一入口，各端就不用再分别复制安装。 这套方式也可以直接让 Codex 或其他能操作本…

## 使用/获取

- 一般做法：按原项目 README / `SKILL.md` 的说明，把 Skill 导入 WorkBuddy（或放入技能目录）。
- ⚠️ 安装第三方 Skill 前请审阅其来源、许可证、会访问的文件/账号/网络权限。
